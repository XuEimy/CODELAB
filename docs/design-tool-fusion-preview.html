1 + 3 融合，但拆成多窗口协同

不是把所有东西塞进一个设计工具窗，而是把参数目录、对象检查器和 vibe 控制层分成 3 个协同窗口

这样你既能保留 参数目录主结构，又能把 vibe design 放进来，而且不会挤到看不清。 用户看到的是三个配合工作的窗口，底层其实还是同一套 游戏 schema 仍在底层 提供数据。

为什么要拆窗
参数目录窗 负责“这个游戏里到底有哪些对象、哪些类别可以调”。它是导航，不负责深调。
对象检查器 负责具体参数，比如 植物 > 樱桃炸弹 的攻击范围、所需能量、杀伤力。
vibe 控制窗 负责“危险、春日、软萌、机械”这种抽象氛围，并明确显示它影响了哪些参数。

1. 先走目录

先从参数目录窗里进入对象类别。这里始终是稳定的通用骨架，未来换别的游戏也不变。

2. 再看对象

对象检查器只负责深层调参。比如樱桃炸弹、二段跳、巡逻兵、地块毒雾，都在这一窗里精调。

3. 最后叠 vibe

vibe 控制窗像一个高层滤镜，但不是黑盒，它会把影响到的参数列表明确展示出来。

我的建议是：真正实现时，先把 参数目录窗 + 对象检查器 落地，然后再接入 vibe 控制窗。 这样你既能马上得到结构化调参，又能为后面的 vibe design 留足空间。
